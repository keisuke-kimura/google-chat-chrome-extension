# Chat Booster for Google Chat

Google Chat を Slack っぽく使うための Chrome 拡張（Manifest V3 / ビルド不要）。

**検知は Google Chat API（ユーザー認証）で行います。** DOM スクレイピングではないので、
Chat の画面構造が変わっても通知は壊れません。

- **メンション即通知** — 参加している**全スペース**を横断して自分宛の `@メンション` を検知し、デスクトップ通知＋通知音
- **通知音を選べる** — 7種のプリセット（チャイム / ピン / マリンバ / ポップ / ノック /
  アラート / サトル）から選択。すべて Web Audio で合成しているので音声ファイルの同梱ゼロ。
  手持ちの mp3 等を読み込むこともできます。設定画面の「▶ 試聴」でその場で確認できます
- **正確な判定** — API の `USER_MENTION` アノテーションを見るので、「本文に名前が出ただけ」の誤検知なし
- **Chat を開いていなくても動く** — バックグラウンドでポーリング
- **未読の一覧** — 未読のあるスペースを件数つきで一覧表示（Slack のサイドバー相当）。
  Chat 本体の既読状態をそのまま映すので、Chat で読めばここからも消えます
- **未読バッジ** — ツールバーアイコンに未読メンション数
- **メンションフィード** — サイドパネルに全スペース横断の一覧（Slack の「アクティビティ」相当）
- **ブックマーク保存** — ホバーして「★ 保存」、または <kbd>Alt</kbd>+<kbd>S</kbd>（Slack の「後で」相当）
- **スペースのミュート** — うるさいスペースを一覧から 🔕 で除外

## セットアップ

**この拡張は、あなた自身の Google Cloud プロジェクトを使います。**
クライアント ID は拡張に埋め込まれておらず、設定画面で入力する方式です。
そのため、あなたのデータが作者や第三者のプロジェクトを経由することはありません。

初回だけ Cloud 側の設定が必要です（**15 分ほど**）。

### 1. 拡張をインストールして、リダイレクト URI を控える

インストール後、オプション画面（拡張アイコンを右クリック →「オプション」）を開くと
**「承認済みのリダイレクト URI」** が表示されます。
`https://xxxxxxxx.chromiumapp.org/` の形式です。あとで使うのでコピーしておいてください。

### 2. Google Cloud プロジェクトを作る

[Google Cloud Console](https://console.cloud.google.com/projectcreate) でプロジェクトを新規作成（既存でも可）。

### 3. Google Chat API を有効化して「設定」を埋める

1. [API ライブラリ](https://console.cloud.google.com/apis/library/chat.googleapis.com) で
   **Google Chat API** を有効化
2. **Chat API の「設定」タブで、アプリ名・アバターURL・説明を入力して保存**

> ここは省略できません。ユーザー認証で読み取るだけの用途でも、Chat API は
> アプリの構成が空だと `403` を返します。
> 対話機能は使わないので、アプリ名は `Chat Booster`、アバターは適当な画像 URL、
> 説明は `個人用の通知ブースター` 程度で構いません。

### 4. OAuth を設定する

1. **OAuth 同意画面** を作成
   - 会社の Google Workspace アカウントなら **ユーザーの種類「内部 (Internal)」** を選ぶ
     → Google の審査なしで使えます
   - 「外部」しか選べない場合は、テストユーザーに自分を登録すれば審査なしで使えます
     （ただし後述のトークン失効に注意）
2. **認証情報** → 「認証情報を作成」→ **OAuth クライアント ID**
   - アプリケーションの種類: **ウェブ アプリケーション**
   - **承認済みのリダイレクト URI**: 手順 1 でコピーした
     `https://xxxxxxxx.chromiumapp.org/` を追加
3. 発行された **クライアント ID**（と、できれば **クライアント シークレット**）をコピー

### 5. 拡張に貼って接続する

オプション画面の「接続」セクションに貼り付け、**「Google アカウントに接続」**。

**クライアント シークレットは任意ですが、入れることを強く推奨します。**

| | シークレットあり | シークレットなし |
| --- | --- | --- |
| 認証方式 | 認可コード + PKCE | インプリシット |
| リフレッシュトークン | ○ | ✗ |
| 再ログイン | 基本的に不要 | 約1時間ごとにトークン失効。Google のセッションが生きていれば無画面で取り直すが、切れていると再接続が必要 |

バックグラウンドで動き続ける拡張なので、シークレットありの方が確実に安定します。

## 要求するスコープ

| スコープ | 用途 |
| --- | --- |
| `chat.spaces.readonly` | 参加しているスペース／DM の一覧 |
| `chat.messages.readonly` | 各スペースの新着メッセージ本文とメンション情報 |
| `chat.users.readstate` | 既読状態の読み書き（「Chat 本体の未読も既読にする」設定を使う場合のみ書き込み） |
| `openid` / `userinfo.profile` | 自分のユーザー ID（メンション相手が自分かの判定に使う） |

`chat.messages.readonly` は Google の**機密スコープ (sensitive)** です。
`chat.messages`（書き込み含む）や `chat.import` などの**制限付きスコープ (restricted)** とは
別区分で、年次のサードパーティ security assessment までは求められません。

| 同意画面の設定 | 審査 | 備考 |
| --- | --- | --- |
| **内部**（同一 Workspace 組織） | **不要** | 社内配布ならこれ。いちばん楽 |
| 外部＋テストユーザー（100人まで） | 不要 | 公開ステータスが「テスト」の間は**リフレッシュトークンが7日で失効**し、週1で再認証が要る |
| 外部＋一般公開 | 必要 | ブランド確認が中心の審査 |

取得したデータは **すべてローカル**（`chrome.storage`）に保存され、外部へ送信されません。

## 使い方

| 操作 | 内容 |
| --- | --- |
| ツールバーのアイコン / <kbd>Alt</kbd>+<kbd>Shift</kbd>+<kbd>S</kbd> | サイドパネル（メンション・保存済み）を開く |
| メッセージにホバー → **★ 保存** | ブックマークに追加 |
| <kbd>Alt</kbd>+<kbd>S</kbd> | カーソル上のメッセージを保存。テキスト選択中はその範囲だけ保存 |
| メッセージにホバー → **🔗** | そのメッセージへのリンクをコピー |
| フィードの **🔕** | そのスペースの通知を止める |

ショートカットの変更は `chrome://extensions/shortcuts` から。

## 通知が届くまでの時間

Chat API には**拡張機能へ push する仕組みがありません**
（Workspace Events API の配信先は Pub/Sub で、受けるサーバが必要）。
そのためポーリングしています。

| 状況 | 気づくまで |
| --- | --- |
| Chat のタブを開いている | **数秒**（画面の変化を合図に即取得。オプションの「画面の変化を合図に…」がオン時） |
| サイドパネルを開いている | 約 20 秒 |
| どちらも閉じている | ポーリング間隔（既定 60 秒 / 下限 30 秒） |

間隔はオプションで変更できます。短くするほど API 使用量が増えます。

## 他の人に配る

### まず押さえるべき制約

**「パッケージ化されていない拡張機能を読み込む」で入れた拡張の ID は、フォルダの絶対パスから
決まります。** つまり配った相手ごとに ID が変わり、拡張 ID に紐づく OAuth クライアントが
一致せず、**受け取った人は接続できません。**

これを解くには、拡張 ID を固定する必要があります。

```bash
bash tools/make-key.sh   # 署名鍵を作り、manifest.json に貼る "key" と固定 ID を表示
```

表示された `"key"` を `manifest.json` に追加すると、誰がどこに置いても ID が同じになり、
**1 つの OAuth クライアントを全員で共有**できます。
（Chrome ウェブストアで公開する場合は ID をストアが発行するので `"key"` は不要です。
 `key.pem` は秘密鍵なので絶対にコミットしないでください。`.gitignore` 済み）

### 配布方法の比較

| 方法 | 相手の手間 | 自動更新 | 準備 |
| --- | --- | --- | --- |
| **A. 管理コンソールで強制インストール** | **ゼロ**（勝手に入る） | ○ | Workspace 管理者権限。ウェブストア公開が前提 |
| **B. ウェブストアに「限定公開」** | リンクを開いて「追加」 | ○ | 登録料 $5（買い切り）＋ストア審査 |
| **C. zip を配って各自で読み込む** | 開発者モードON＋展開＋読み込み | ✗（手動で配り直し） | なし。すぐできる |

**社内に配るなら A か B を推奨。** 同じ Workspace なら OAuth 同意画面を「内部」にできるので
Google の審査も不要で、C の弱点（毎回出る「デベロッパーモードの拡張機能を無効にする」警告、
更新のたびに配り直し）も避けられます。

### 手順

**共通の準備**

1. `bash tools/make-key.sh`（C の場合のみ。A / B では不要）
2. OAuth 同意画面を **「内部」** に設定
3. OAuth クライアント（種類: Chrome 拡張機能）のアイテム ID を、固定した拡張 ID に設定
4. `manifest.json` の `oauth2.client_id` を実際の値に差し替え
5. `bash tools/pack.sh` → `dist/chat-booster-<version>.zip`

**A. 管理コンソールで強制インストール（相手の手間ゼロ）**

B でウェブストアに公開したうえで、Google 管理コンソール →
アプリ → 追加のアプリ → Chrome アプリと拡張機能 で、対象の拡張を
「**強制インストール**」に設定。対象 OU のメンバー全員に自動配布されます。

**B. ウェブストアに限定公開**

1. [Chrome Web Store デベロッパーダッシュボード](https://chrome.google.com/webstore/devconsole)
   に登録（初回のみ $5）
2. zip をアップロード
3. 公開設定を **「限定公開 (Unlisted)」**（リンクを知っている人だけ）または
   **「限定公開: 自分のドメイン内のみ」** にする
4. 審査通過後、リンクを配れば「Chrome に追加」だけで入ります

**C. zip を配る（すぐ試したいとき向け）**

zip と一緒に、受け取る人向けの手順を添えてください。

1. zip を展開
2. `chrome://extensions/` → デベロッパーモードをオン
3. 「パッケージ化されていない拡張機能を読み込む」→ 展開したフォルダ
4. オプション画面で「Google アカウントに接続」

> `.crx` ファイルを直接配る方法は使えません。ウェブストア以外から入手した `.crx` は
> Chrome が既定でインストールを拒否します。

## 構成

```
manifest.json
src/
  background.js          # 認証・スケジュール・UI からの要求の窓口
  lib/
    auth.js              # OAuth（利用者が入力した client id で launchWebAuthFlow）
    chat-api.js          # Chat REST API クライアント（リトライ・ページング）
    poller.js            # ポーリングとメンション判定（ここが検知の本体）
    notify.js            # 通知・通知音・バッジ
    store.js             # storage.local のアクセサ
    defaults.js          # 設定のデフォルト値
  content/content.js     # ★保存ボタン と「新着っぽい」合図の送信のみ
  offscreen/             # 通知音を鳴らすための offscreen document
  sidepanel/             # メンションフィード / 保存済み一覧
  options/               # 設定・接続画面
tools/
  make_icons.py          # アイコン生成（標準ライブラリのみ）
  make-key.sh            # 拡張 ID を固定する署名鍵の生成
  pack.sh                # 配布用 zip / crx の作成
```

保存件数はメンション 300 件 / 保存済み 1000 件で、古いものから破棄します。

## 既知の制約

- **リアルタイムではありません。** 上記のとおりポーリングです。1 秒以内の通知が要るなら
  Pub/Sub を受けるサーバ（Cloud Run など）を別途立てる構成が必要になります。
- **スペース数に比例して API 呼び出しが増えます。** 1 回のポーリングで
  「スペース数ぶん」のリクエストを投げます（同時実行は 5 本まで）。
  参加スペースが極端に多い場合は間隔を長めに、不要なスペースは 🔕 でミュートしてください。
- **管理者がサードパーティアプリを制限している Workspace では接続できません。**
  その場合は管理コンソール側での許可が必要です。
- **`chrome.identity` を使うため、Chrome 本体に対象の Google アカウントでログインしている必要があります。**
  複数アカウントを使い分けている場合は、Chrome のプロファイルを分けるのが確実です。
- **★保存ボタンだけは DOM に依存しています。** Chat の画面構造が変わると、このボタンが
  出なくなる可能性があります（`src/content/content.js` の `MESSAGE_SELECTORS`）。
  壊れても**通知機能には影響しません**。サイドパネルのフィードからも保存できます。
- グループ chat と DM は、最初のメッセージが送られるまでスペース一覧に出てきません（API の仕様）。
- **未読一覧はスペース単位です。** Chat のスレッド単位の既読状態までは見ていないため、
  スレッド返信だけが未読のときの件数が Chat 本体の表示と食い違うことがあります。
- 未読一覧は1スペースあたり2リクエスト使うので、既定では 5 分間隔にしています
  （オプションで変更・無効化できます）。

## 料金

**Google Chat API の利用料は無料です。** リクエスト課金はなく、請求先アカウントの
紐付けも不要です。Google Workspace の契約に含まれます。

代わりに<b>レート制限</b>があり、超えると課金ではなく `429` エラーが返ります。

| 制限 | 値 |
| --- | --- |
| プロジェクトあたり メッセージ読み取り | 3,000 回 / 60 秒 |
| ユーザーあたり 読み取り | 15 回 / 秒 |
| スペースあたり 読み取り | 15 回 / 秒 |

この拡張の使用量は、30 スペース・既定設定（メンション 60 秒間隔＋未読 5 分間隔）で
**毎分およそ 40 リクエスト**。上限に対してかなり余裕があります。
同時実行も 5 本に制限しているので、秒あたりの制限にも当たりません。
429 を受けたら 5 分間バックオフします。

お金がかかるのは次の場合だけです。

- Chrome ウェブストアでの公開（**初回 $5 の買い切り**、拡張を配布する人のみ）
- Pub/Sub や Cloud Run など、他の GCP 有料サービスを併用する場合（この拡張は使いません）

## 開発メモ

ビルド不要。ファイルを編集したら `chrome://extensions/` で拡張のリロード。
content script を変えたときは Chat のタブもリロード。

```bash
python3 tools/make_icons.py   # アイコンを作り直す
```

デバッグは `chrome://extensions/` の「Service Worker」リンクから DevTools を開くと、
ポーリングのエラーが `[chat-booster]` プレフィックスで出ます。
